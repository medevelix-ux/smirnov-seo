1. Назначение прототипа

Прототип демонстрирует Telegram-сценарий запуска создания коммерческого предложения внутри Вебтроники.

  1. Бот по шагам собирает настройки.
  2. Передаёт задачу в Вебтронику.
  3. Сообщает о принятии задачи и показывает её статус.
  4. После готовности присылает ссылку и файл КП.

В этой HTML-версии интеграция имитируется JavaScript без реальных API-запросов.

2. Общий дизайн и UX
  • Интерфейс имитирует Telegram Desktop и адаптируется под мобильный экран.
  • Сообщения бота расположены слева, пользователя — справа.
  • Используются inline-кнопки, время сообщений, состояние «печатает…» и автоматическая прокрутка.
  • DEV-панель постоянно видна на широком экране и открывается поверх чата на узком.
  • Все действия выполняются без перезагрузки страницы.
3. Последовательность диалога
  1. Команда «Создать КП».
  2. Ввод URL продвигаемого сайта.
  3. Выбор поисковой системы.
  4. Выбор региона с учётом поисковой системы.
  5. Настройка сводного отчёта Яндекс + Google.
  6. Ввод обязательных доменов одним сообщением.
  7. Выбор режима обязательных доменов.
  8. Ввод исключаемых доменов.
  9. Итоговая проверка параметров.
  10. Запуск задачи внутри Вебтроники.
  11. Сообщение о принятии задачи.
  12. Автоматическое обновление статуса.
  13. Получение готового КП в Telegram.
4. Команда «Создать КП»

Начальное сообщение содержит короткое объяснение и кнопку Создать КП. После клика бот запускает пошаговый сценарий и запрашивает URL сайта.

Кнопка полного сброса в шапке очищает состояние прототипа и возвращает пользователя к начальному экрану.

5. URL продвигаемого сайта

Поле обязательное. Допускаются адреса с протоколом, www и путём: example.ru, https://www.example.ru/catalog/.

  • Проверяется наличие корректного домена и доменной зоны.
  • Запрещаются пробелы и недопустимые символы.
  • Для дальнейшей логики значение нормализуется до домена без www.
  • При ошибке бот предлагает повторный ввод или отмену сценария.
6. Выбор поисковой системы

Пользователь выбирает одну из двух inline-кнопок: Яндекс или Google.

От выбора зависит следующий набор регионов. При последующем изменении поисковой системы ранее выбранный регион должен быть проверен заново.

7. Регионы Google

Для Google доступны только три кнопки:

  • Москва;
  • Киев;
  • Нью-Йорк.

Ручной ввод другого города для Google не предусмотрен.

8. Регионы Яндекса и ручной ввод

Быстрые кнопки: Москва, Санкт-Петербург, Екатеринбург, Н. Новгород, Краснодар и «Другой…».

После выбора «Другой…» пользователь вводит город вручную. Нормализация игнорирует регистр, пробелы, точки, дефисы и иные разделители. Например, ростов на дону преобразуется в Ростов-на-Дону.

Два разных сообщения об ошибке:

  • Если город не распознан: «Город указан неверно. Проверьте написание и попробуйте ещё раз».
  • Если город существует, но отсутствует в ограниченном справочнике Вебтроники: «Город отсутствует в списке доступных регионов. В таком случае рекомендуем указать Москва».

В рабочей версии справочник поддерживаемых регионов должен приходить из Вебтроники, а не храниться в коде бота.

9. Сводный отчёт Яндекс + Google

Бот обязательно поясняет: «Данная функция запускает анализ в обеих ПС по региону Москва».

  • При включении поисковая система становится «Яндекс + Google».
  • Регион автоматически устанавливается «Москва».
  • Если был выбран другой регион, бот сначала запрашивает подтверждение изменения.
  • Если пользователь отказывается, сохраняются текущие поисковая система и регион.
10. Обязательные домены

Пользователь отправляет один или несколько доменов одним сообщением, каждый домен — с новой строки. Шаг можно пропустить.

  • Каждая строка валидируется отдельно.
  • Допускаются URL с протоколом, www и путём.
  • Значения нормализуются до домена.
  • Удаляются дубликаты.
  • Запрещено добавлять продвигаемый домен.
  • Корректные строки сохраняются, даже если часть списка содержит ошибки.

Для ошибочных строк бот показывает причину и предлагает исправить только их либо продолжить.

11. Режим обязательных доменов

После ввода доменов пользователь выбирает один из трёх вариантов:

  1. Всегда добавлять в анализ — независимо от наличия в выдаче.
  2. Учитывать только при наличии в выдаче — включать только найденные в поиске домены.
  3. Анализировать только указанные домены — автоматический поиск конкурентов не выполняется.

Если список доменов пуст, бот предлагает вернуться к их добавлению либо пропустить настройку режима.

12. Исключаемые домены

Вводятся одним сообщением, каждый домен — с новой строки. Применяется та же валидация и нормализация.

  • Нельзя исключить продвигаемый домен.
  • Один домен не может одновременно находиться в обязательном и исключаемом списке.
  • При конфликте бот сообщает причину и не добавляет спорное значение.
13. Итоговая проверка и редактирование

Бот показывает карточку со всеми собранными параметрами и кнопками запуска, изменения и отмены.

Раздел «Изменить параметры» открывает отдельные кнопки для URL, поисковой системы, региона, сводного отчёта, обязательных доменов, режима и исключений.

После изменения одного поля пользователь возвращается к итоговой карточке. Связанные поля перепроверяются автоматически.

14. Создание задачи в Вебтронике

После подтверждения интерфейс показывает «Передаю параметры в Вебтронику…», затем карточку принятой задачи:

  • номер задачи;
  • домен;
  • время запуска;
  • начальный статус;
  • ссылку на задачу внутри Вебтроники.

В рабочей версии backend должен отправить настройки в API Вебтроники и сохранить полученный ID задачи вместе с Telegram user ID.

15. Автоматическое обновление статуса

Рекомендуется редактировать одно статусное сообщение, чтобы не засорять чат.

Пример последовательности: подготовка данных → анализ выдачи → формирование КП → финальная проверка.

Процент разрешено показывать только при наличии реального прогресса от API. Переключатель выше демонстрирует оба варианта.

16. Готовое КП

После завершения бот отправляет карточку результата с доменом, поисковой системой, регионом и номером задачи.

Кнопки: «Открыть КП», «Скачать PDF», «Открыть в Вебтронике», «Создать ещё одно КП».

В прототипе «Открыть КП» показывает демонстрационный предпросмотр, а «Скачать PDF» генерирует простой тестовый PDF.

17. Ошибка формирования КП

Предусмотрен отдельный сценарий ошибки. Его можно включить переключателем в начале DEV-панели.

Кнопки после ошибки: повторить запуск, изменить параметры или открыть задачу в Вебтронике. При повторе используются уже собранные параметры.

18. Техническая структура прототипа
  • Один автономный HTML-файл.
  • Внутри находятся разметка, стили, JavaScript, демонстрационные справочники и комментарии.
  • Внешние библиотеки и сетевые запросы не используются.
  • Состояние хранится в объекте JavaScript до перезагрузки страницы.
  • Поддерживаются desktop, tablet и mobile.
19. Будущая интеграция

Рекомендуемый поток:

Telegram → backend бота → API Вебтроники → ID задачи → webhook или polling → готовое КП → Telegram

Необходимо реализовать:

  1. авторизацию и Telegram user ID;
  2. создание задачи через API;
  3. сохранение связи пользователь ↔ задача ↔ проект;
  4. webhook от Вебтроники либо периодическую проверку статуса;
  5. получение ссылки или файла;
  6. повторные попытки и обработку ошибок;
  7. защиту от дублирующего запуска;
  8. проверку прав доступа к задаче и документу.
